# 每轮测试档案与确认卡

本文件是 `functional-testing` skill 的模板集合：开跑前的「数据确认卡」、UI 自动化的「测试项告知」、以及每轮结束后的「测试档案」。

---

## 1. 数据确认卡（接口测试 / 模块功能测试，执行前必须发给用户确认）

```markdown
本轮测试数据确认

- 测试目标：<这轮要验证的需求点/验收标准>
- 覆盖范围：<模块、接口路径清单>；不覆盖：<明确排除的项>
- 执行逻辑：<顺序 / 分支 / 并行；具体顺序：A → B（B 使用 A 返回的 id）；分支条件与数据；并行诉求 v1 按串行执行>
- 环境/地址：<env 名> / <baseUrl>
- 账号与凭据：<环境变量名或 .ft/credentials.local.json 里的变量名>（仅测试/开发环境；不在聊天里复述值）
- 前置数据：<需要预先存在的账号、数据、开关、灰度状态>
- 本轮将创建/修改的数据：<字段、唯一后缀、影响范围>
- 清理方式：<删除接口/重置脚本/无需清理的原因>
- 写操作放行：<需要放行的 (method, pathPattern) 白名单；不需要则写「无」>
- 登录用例：<有登录档案：本轮会先跑 LOGIN-001 登录取令牌，计入用例总数；登录接口写操作已放行：是/否。无登录：不适用>

请确认以上是否符合预期，确认后开始执行。
```

规则：
- 用户确认后再调用 `ft_http_run`；未确认不要开跑。
- 用户改了数据或范围，更新确认卡后重新确认。
- 凭据一律只写环境变量名，不写值。

---

## 2. UI 自动化测试项告知（不需要用户确认数据，只需告知）

```markdown
本轮 UI 自动化将覆盖

- 页面/路由：</user/list、/user/detail/:id>
- 流程：<登录 → 列表加载 → 新增用户 → 断言表格出现新行>
- 关键动作：<goto / click / fill / waitForResponse>
- 断言点：<表格文本、toast 提示、行数>
- 登录态：<storageState 文件 / cookie / 无登录>
- 证据：失败截图 + 控制台错误 + 失败请求记录
```

规则：
- 只告知覆盖项，不要求用户确认数据。
- 若流程涉及删除/批量修改等不可逆操作，仍需单独确认是否允许。
- 选择器优先 `testid=`；其次 `css=`；`text=` 只用于稳定文案。

---

## 3. 每轮测试档案（执行后写入 `.ft/runs/<runId>/plan.md`）

```markdown
# <runName> 测试档案

- runId：<runId>
- 时间：<startedAt> ~ <finishedAt>
- 环境：<env> / <baseUrl>
- 测试类型：单测接口 | 单测页面 | 模块功能（接口 + UI + 前后端一致性）

## 1. 测试目标
<这轮要验证/回答什么；对应需求点、验收标准、回归范围>

## 2. 覆盖范围
- 覆盖：<模块 / 接口清单 / 页面路由 / 流程>
- 不覆盖：<明确排除项及原因>
- 执行逻辑：<顺序 / 分支 / 并行；串行顺序 A → B；依赖：B 用 A 的 `<字段>`；分支：<条件 → 用例>；并行：<说明 v1 按串行执行>

## 3. 测试数据
- 账号与凭据：<环境变量名>
- 前置数据：<预置数据与状态>
- 本轮构造的数据：<唯一后缀、创建/修改的实体>
- 清理：<已清理 / 清理方式 / 无需清理>

## 4. 异常复现方式
### <caseId> <caseName>（<产品缺陷|用例缺陷|环境问题>）
- 前置条件：<数据、开关、账号>
- 最小请求：`<METHOD> <URL>`，并附 headers/body（JSON 原样贴出）
- 或 UI 步骤：`<goto → click → fill → assert>`
- 期望：<契约/需求>
- 实际：<状态码/字段/页面表现>
- 证据：`.ft/runs/<runId>/results.jsonl#<caseId>`、截图 `<path>`
- 复跑：`ft_http_run` 读取 `.ft/runs/<runId>/suite.json`，或用同一 runId 重跑

## 5. 结论
- 通过率：<N 通过 / M 总数>
- 疑似产品缺陷：<列表>
- 用例/环境问题：<列表>
- 遗留风险 / 建议回归范围：<...>
```

规则：
- 四节内容缺一不可：目标、覆盖范围、测试数据、异常复现方式。
- 没有异常时，第 4 节写「无失败用例」，并给出通过用例的抽样断言，证明真的校验过。
- 报告（`ft_report` 产出的 `report.md`）与最终回复都要能引用这份档案。
