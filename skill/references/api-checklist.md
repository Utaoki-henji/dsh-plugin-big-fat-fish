# 接口用例设计清单

按模块逐项过；不是每一项都要测，按风险取舍。

## 1. 正常路径
- [ ] 必填字段齐全、类型正确 → 成功
- [ ] 分页/排序/筛选参数组合（默认值、边界页码）
- [ ] 创建后能查询到（链路用例：创建 → 查询 → 更新 → 删除）
- [ ] 幂等接口重复调用结果一致

## 2. 参数边界
- [ ] 字符串：空串、最短、最长、超长、前后空格、emoji
- [ ] 数字：0、负数、小数、超大值、精度
- [ ] 枚举：合法值、非法值、大小写
- [ ] 日期：格式错误、时区、跨天
- [ ] 数组：空数组、单元素、重复元素、超长
- [ ] 嵌套对象：缺字段、多字段、null

## 3. 异常与错误码
- [ ] 缺必填 → 400 + 明确错误码/提示
- [ ] 类型错误 → 400
- [ ] 资源不存在 → 404
- [ ] 未登录 → 401；无权限 → 403
- [ ] 冲突（唯一键重复）→ 409
- [ ] 服务端异常 → 500 且有日志/错误码，不泄漏堆栈
- [ ] 错误响应结构符合统一规范

## 4. 权限与越权
- [ ] 不同角色访问同一接口
- [ ] 水平越权：用 A 的 id 访问 B 的数据
- [ ] 未登录/过期 token
- [ ] 管理端接口普通用户不可达

## 5. 契约一致性
- [ ] 字段名、类型、可空性与文档一致
- [ ] 响应包结构（code/message/data）一致
- [ ] 新增字段是否破坏旧客户端（兼容性）
- [ ] Content-Type、字符编码、时间格式

## 6. 数据与状态
- [ ] 状态迁移是否合法（如 待支付 → 已支付，不能反向）
- [ ] 软删除后查询/重复删除
- [ ] 并发写同一资源（至少记录现状）
- [ ] 事务：部分失败是否回滚

## 7. 安全与健壮性（功能视角）
- [ ] SQL 注入 / XSS 字符串在接口层的表现（不传脚本，传异常字符）
- [ ] 超大请求体、超长 URL 被拒绝
- [ ] 文件类型/大小限制

## 8. 多接口联动与执行逻辑（强制先确认，禁止猜测）
- [ ] 执行方式已向用户确认：顺序 / 分支 / 并行
- [ ] 具体顺序已确认：先调哪个、后调哪个；哪些用例依赖前一个的返回
- [ ] 依赖关系已记录：A 的哪个字段（JSONPath）传给 B 的 path/query/headers/body
- [ ] 分支场景：条件由谁触发、各自准备什么前置数据、拆成哪些独立用例
- [ ] 并行诉求：已如实说明 v1 固定串行执行（`concurrency=1`），按确认顺序跑
- [ ] 初始化/清理顺序：teardown 按依赖逆序执行，不破坏其他用例数据
- [ ] 没有从代码结构自行推断调用链；不确定的都问过用户
