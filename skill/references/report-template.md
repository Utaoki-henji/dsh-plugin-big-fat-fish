# 测试报告模板

报告是给不看聊天记录的人看的。每轮报告都要能回答四件事：**测什么（目标）、测到哪（覆盖范围）、用什么测（测试数据）、失败怎么复现**。

```markdown
# <项目/模块/版本> 功能测试报告

## 0. 本轮档案
- 测试目标：<对应需求点 / 验收标准 / 回归范围>
- 覆盖范围：<模块、接口路径、页面路由清单>；不覆盖：<明确排除项>
- 测试数据：<环境、账号来源（环境变量名）、前置数据、构造数据、清理方式>
- 测试类型：单测接口 | 单测页面 | 模块功能（接口 + UI + 前后端一致性）
- 档案文件：`.ft/runs/<runId>/plan.md`

## 1. 概览
- 环境：<env> / <baseUrl>
- 时间：<startedAt> ~ <finishedAt>
- 用例：共 N，通过 X，失败 Y，错误 Z，阻塞 W，跳过 S
- 通过率：XX%

## 2. 失败明细
### TC-007 非法年龄应返回 400
- 请求：POST /api/users
- 期望：status = 400；实际：200
- 证据：results.jsonl#TC-007
- 复现：见 suite.json#TC-007（前置数据 + 最小请求 + headers/body 见档案第 4 节）
- 初判：产品缺陷（缺少参数校验）

## 3. 错误与阻塞
- 网络/环境错误：
- 被策略拦截：

## 4. 警告
- 延迟超标（未判失败）：
- 已知问题豁免：

## 5. 结论与建议
- 疑似产品缺陷：N 个（列表）
- 用例/环境问题：N 个
- 遗留风险：
- 建议回归范围：
```

补充要求：

- 第 0 节四项不能省略；工具生成的 `report.md` 不包含这些信息时，用 `plan.md` 补全并在报告里引用。
- 接口/模块测试必须增加「异常输入与边界值覆盖」小结：覆盖了哪些参数、哪些变异类别（必填/空值/类型/超长/超界/注入/分页/时间/鉴权）、观察到的异常处理行为（是否 500、是否截断、注入串是否按字面值处理），判读规则见 `negative-input-checklist.md`。
- 失败明细必须给到「最小复现」：前置条件、请求方法/URL/headers/body（或 UI 步骤）、期望与实际、证据路径、复跑方式。
- 模块功能测试要单独列出「前后端一致性」结论：同一数据下 UI 展示与接口返回是否一致（字段、口径、单位、分页/排序、错误提示）。
- 有登录档案的项目：概览里注明登录用例 `LOGIN-001` 是否通过、令牌获取方式（只写接口与变量名，不写令牌值）；登录失败导致的 401/403 归环境/凭据问题。
- 截图可能包含个人信息，报告里注明存放位置，不贴原始响应体全文。
